## 12. Environment Limitations (stated plainly)

1. **No network access to binaries.prisma.sh.** This is the single
   blocking issue preventing a 100%-clean backend typecheck/build in
   this sandbox. `npx prisma generate` must be run in any environment
   with normal internet access (including the GitHub Actions CI job
   already configured for this, and any real deployment) before the
   backend will start. Every line of code that consumes Prisma types
   was written against the schema as specified, and the schema itself
   was manually reviewed for syntax correctness -- but the
   generated-client type-checking pass itself could not be completed
   here.
2. **No Docker daemon available.** Dockerfiles and Compose
   configuration were authored and had every path reference manually
   verified against the actual repository structure, but no image was
   actually built or container actually run in this session.
3. **No live PostgreSQL instance available.** All database-dependent
   logic (auth, checkout, entitlements, coupons, wishlist) was verified
   either by (a) extracting and independently executing the exact
   business-logic formulas as standalone Node scripts with real
   assertions, or (b) static cross-referencing of route definitions,
   middleware chains, and schema constraints. No live HTTP request was
   made against a running instance of this backend.

None of these are code defects -- they are sandbox network/tooling
restrictions. Section 11 represents the strongest verification
achievable without those two resources, and every PASS is backed by an
actual executed command or test during this session, not an assertion.
